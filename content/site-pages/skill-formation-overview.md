# Create and integrate a reusable skill

## Purpose

Combine bounded perspectives from the Personas who perform the work, then formalize a reusable capability without losing its context.

This is the existing authored Site explanation, moved out of the catalog page. No authoritative process document is bound to this Playbook identity yet. The sequence below is illustrative, not an execution contract or evidence that a request followed it.

## Illustrative sequence

### Frame: scope the capability

Define the outcome, boundary, and reason this deserves a Skill. Compare neighboring capabilities before proposing a new identity.

### Select: choose the lenses

Invite only the Personas whose work reveals a distinct part of the capability.

### Synthesize: compare the perspectives

Find shared triggers, actions, tools, decisions, and quality signals while preserving distinct applications and uncertainty.

### Formalize: structure the Skill

Use the existing Skill authoring route to turn the shared core into a structured Skill with explicit boundaries. Consult [Skill authoring guidance](guide.html#skill-authoring).

### Validate: test quality and reuse

Check that the Skill is recognizable, non-duplicative, and useful in a new context.

### Reconcile: integrate the system

Review affected Personas, workflows, docs, relationships, and revision history. Apply only authorized changes; reconciliation itself is read-only.

## Working material

- Capability brief: outcome, boundary, reason for creation, and neighboring Skills.
- Persona lens set: selected contributors and the distinct evidence each adds.
- Skill draft: shared core, role-specific applications, operating loop, quality signals, and open questions.
- Integration queue: required updates to Personas, workflows, docs, relationships, and revisions.
