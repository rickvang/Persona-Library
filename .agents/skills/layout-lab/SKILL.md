# Layout Lab — repository adapter

Use [Adaptive UX Design](https://github.com/rickvang/SkillRepo/blob/main/codex/methods/adaptive-ux-design/SKILL.md) and its [concept/composition method](https://github.com/rickvang/SkillRepo/blob/main/codex/methods/adaptive-ux-design/references/concept-composition.md) with the existing brief. That package owns framing, exploration depth, content/visual development, direction review and critique. This adapter has no separate brief, persona panel or idea quota. The metadata value `persona_applied` is a legacy repository classification; invoking an agent persona is not required.

## Repository boundary

- Read the repository's applicable instructions and [prototyping route](../../../content/orientation/prototyping.json). Recover the current prototype/artifact and decisions before resuming.
- Keep experimental files in the existing prototype-owned surface with an identifier/status. Live catalogs, counts and production flows must not depend on prototype records.
- Compare representative content/tasks fairly. If content strategy itself differs, explain that difference and avoid attributing the whole result to layout.
- Show a reviewable concept and its tradeoffs. Selection records direction; apply existing user authorization for any live change and do not infer broader permission from a selection alone.
- For authorized promotion, inspect affected source/consumer boundaries, apply the scoped change and repository checks, preserve the decision in the existing record, and run one [Change Impact Reconciliation](../change-impact-reconciliation/SKILL.md) pass. Pure exploration needs isolation checks, not a live reconciliation project.

Return the artifact, meaningful differences, selection/uncertainty, affected scope and actual checks. If the shared package cannot be retrieved, report that dependency gap; do not silently reactivate the retired workflow.

Prior method and historical scenarios remain in Git history; they do not define current concept quotas or a mandatory output packet.
