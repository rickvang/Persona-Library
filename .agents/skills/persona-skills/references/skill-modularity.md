# Skill modularity and duplication

Classify a request before creating an identity:

1. Existing Skill identity: reuse and add a relationship or application.
2. Primitive unit: portable judgment used by multiple composed capabilities.
3. Composed Skill: a reusable combination of primitives.
4. Persona application: context, priorities, protections, or proficiency that is not portable.
5. Workflow method: a path-specific sequence that should remain with the workflow.
6. Tool-use recipe: capability-to-Tool instructions with prerequisites, mode, fallback, and verification.
7. No new Skill: one-off behavior, simple relationship, or reference.

Compare triggers, decisions, outputs, quality signals, workflow reach, and boundaries before merging or splitting. Similar names are a search signal, not proof of equivalence. Stable IDs and aliases must remain explicit and must not be silently replaced.
