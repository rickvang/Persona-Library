# Skill profile contract

The current `content/library-data.js` record and validator define exact property names and required values. This reference defines the behavior that must remain visible while a profile is researched or proposed.

## Required distinctions

- definition and boundary;
- trigger, inputs, prerequisites, and context;
- decisions, heuristics, observable actions, outputs, feedback, and residual artifacts;
- inspectable quality signals and failure modes;
- workflow reach and Persona-specific applications;
- Tools and recipes as separate relationships;
- evidence status, confidence, resources, validation questions, and revision context.

A Skill is a portable capability. A Persona application explains how a particular role uses it, with local priorities, protections, proficiency, and context. Keep those layers linked rather than flattening them.

## Profile quality

Prefer observable verbs and inspectable outputs. Replace vague claims such as “is strategic” with the decisions, actions, artifacts, and review signals that would demonstrate the capability. If a signal cannot be supported or tested, mark it unknown or a hypothesis.
