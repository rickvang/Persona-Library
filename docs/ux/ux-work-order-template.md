# UX Work Order — optional recovery record

Use only when the task needs a dedicated Work Order execution/recovery packet because Current Work, the issue/pull request and domain artifacts cannot preserve enough unique recovery state. [Adaptive UX Design](https://github.com/rickvang/SkillRepo/blob/main/codex/methods/adaptive-ux-design/SKILL.md) owns the method; this template owns no additional design stages or gates.

Do not create this template for a qualifying small-change-lane change. Use its existing active record. An existing WorkNode retains its Dispatch, Gate, evidence and disposition obligations without duplicate tracking.

When this template is warranted for repository work, follow [Work Orders](../work-orders.md) for placement/lifecycle and the repository's instructions for execution. Link the existing living brief; do not create another project profile, persona panel, evidence pack or mandatory traceability matrix.

## Recovery essentials

- Outcome and north star / existing brief:
- Authorized target, scope/fidelity, constraints and stopping condition:
- Source repository/artifact and revision:
- Current artifact and completed work:
- Consequential decisions and agreed direction:
- Checks/evidence and limitations:
- Blocker or next concrete action / owner:

Add detail only when a future executor needs it to resume safely. Evidence distinguishes observations, sourced claims and hypotheses. Concept approval does not establish end-user benefit. Record only material changes; a progress transcript is unnecessary.
